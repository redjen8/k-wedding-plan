# 결혼 자금 계획 (wedding-budget)

대화로 예산 정보를 모아 `input.json`을 쓰고, `scripts/build_budget.py`로 수식이 살아 있는 엑셀을 만든다. 엑셀은 직접 조립하지 않는다.

범위는 **예식 준비 비용**이다. 혼인신고 시점, 증여세, 신혼부부 대출·청약, 신혼집은 다루지 않는다. 질문이 나오면 범위 밖이라고 말하고 전문가 확인을 권한다.

## 1. 정보 모으기

한 번에 하나씩 묻는다. 모르는 값은 넘어가도 된다.

가장 먼저 신랑·신부 이름(호칭)을 묻는다. 엑셀 기본정보에 들어간다(결제자는 "신랑"/"신부" 같은 역할로 고른다). 밝히기 싫다고 하면 "신랑", "신부"로 둔다.

필수 (없으면 엑셀을 만들 수 없음):
1. 예식일 (YYYY-MM-DD)
2. 지역: `전국`, `서울`, `경인`, `4대 광역시`, `그 외 지역` 중 하나. 인천·경기는 `경인`, 부산·대구·광주·대전·울산은 `4대 광역시`
3. 1인 식대. 모르면 지역 중간값(전국 6만, 서울 8만, 경인 6.2만, 4대 광역시 5.3만, 그 외 5만원)을 쓰고 추정이라고 알린다
4. 보증인원. 모르면 지역 최소 보증인원 중간값(대부분 200명, 4대 광역시 150명)

있으면 좋은 것:
5. 예식 준비에 쓸 수 있는 돈 (신랑/신부별, 자금원별. 신혼집 자금은 빼고)
6. 예상 하객 수 (신랑측/신부측 × 가족·친구·회사·부모님 지인·기타, 대인/소인)
7. 이미 받은 견적이나 계약 내용 (금액, 할인, 계약금·중도금과 날짜, 잔금일)
8. 이미 결제한 내역: 날짜, 항목, 구분(계약금/중도금/잔금/현장 추가금), 금액, **누가**(신랑/신부/공통/양가 부모), **어떻게**(카드/계좌이체/현금), 계좌이체·현금이면 **현금영수증 발급 여부**
9. 소인 식대, 평균 축의금(기본 117,000원), 예비비 비율(기본 3%)

사용자가 기존 예산 엑셀을 첨부하면 (선택 기능):
1. `python3 scripts/dump_xlsx.py 첨부파일.xlsx`로 셀을 덤프한다.
2. 각 행을 아래 기본 항목명에 매핑한 표를 사용자에게 보여주고 확인을 받는다. 맞는 항목이 없으면 `extra_items`로 보낸다.
3. 확인된 값만 `input.json`에 넣는다. 양식이 제각각이므로 추측으로 채우지 않는다.

## 2. input.json 작성

```json
{
  "groom": "신랑", "bride": "신부",
  "wedding_date": "2027-04-17",
  "region": "경인",
  "meal_price": 68000, "child_meal_price": 34000,
  "guaranteed_guests": 220,
  "avg_gift": 117000, "reserve_rate": 0.03,
  "funds": [{"name": "저축", "groom": 18000000, "bride": 16000000}],
  "guests": {"신랑": {"가족": [30, 4], "친구": [40, 0]}, "신부": {"가족": [28, 3]}},
  "items": {
    "대관료": {"budget": 3000000, "quote": 3300000, "discount": 300000,
              "deposit": 1000000, "deposit_date": "2026-05-10",
              "balance_date": "2027-04-17", "status": "계약"},
    "생화 꽃장식": {"budget": "avg"}
  },
  "extra_items": [{"category": "기타", "name": "웨딩슈즈", "budget": 150000}],
  "payments": [
    {"date": "2026-05-10", "item": "대관료", "type": "계약금", "amount": 1000000,
     "payer": "공통", "method": "카드"},
    {"date": "2026-06-20", "item": "스드메 패키지", "type": "계약금", "amount": 500000,
     "payer": "신부", "method": "계좌이체", "receipt": "발급완료"}
  ]
}
```

- 금액 단위는 **원**이다. 사용자가 "300만원"이라고 하면 3000000으로 쓴다.
- `guests` 값은 `[대인, 소인]` 형식이다.
- `items`의 키는 아래 기본 항목명과 정확히 같아야 한다. 다르면 스크립트가 오류를 내고 올바른 이름 목록을 보여준다.
- 항목 필드: `budget`, `quote`, `discount`, `deposit`, `deposit_date`, `middle`, `middle_date`, `balance_date`, `status`(미정/상담/계약/완료), `memo`. 계약금·중도금·잔금과 날짜는 **예정**이다.
- `payments`는 **실제로 낸 돈**이다. 한 건씩 넣는다(최대 200건).
  - 필드: `date`, `item`(지출계획 항목명 또는 extra_items 이름), `type`(계약금/중도금/잔금/현장 추가금/기타), `amount`, `payer`(신랑/신부/공통/신랑측 부모/신부측 부모), `method`(카드/계좌이체/현금), `receipt`(발급완료/미발급/해당없음), `memo`
  - 지출계획의 '납부 완료'와 '남은 금액', 결제자 × 결제수단 합계, 현금영수증 현황이 여기서 계산된다.
- `"budget": "avg"`는 해당 지역 기준값으로 채우고 메모에 `[추정]`을 붙인다. 사용자가 금액을 모르는데 그 항목을 할 계획이 있을 때만 쓴다.
- `식대` 예산은 비워 두면 하객식대 시트의 예상 식대가 자동으로 들어간다. `당일 추가금·예비비`도 자동이다.
- 결제일을 모르면 흔한 패턴을 제안하고, 사용자가 동의하면 날짜를 넣는다. 날짜가 있어야 월별자금에 잡힌다.
  - 웨딩홀: 계약할 때 계약금(총액의 10% 안팎), 나머지(대관료 잔금+식대)는 예식 당일
  - 스드메: 계약금 10%, 중도금은 촬영 1달 전, 잔금은 예식 1달 전
  - 헬퍼비·얼리스타트비 같은 현장 추가금: 해당 일정 당일, 현금인 경우가 많음
- 전체 예시는 `examples/sample_input.json`에 있다.

기본 항목명 (★ = 놓치기 쉬운 비용):
- 예식장: 대관료, 식대, 기본 장식, 생화 꽃장식★, 본식 촬영(홀 제휴), 본식 원판★, 외부 본식스냅, 본식 영상, 사회자, 축가, 주례, 본식 도우미, 부케★, 포토테이블★, 웨딩케이크, 플라워 샤워, 폐백
- 스드메: 스드메 패키지, 스튜디오(단품), 드레스(단품), 메이크업(단품), 원본·수정본★, 헤어변형★, 헬퍼(촬영·본식)★, 드레스 투어 피팅비★, 앨범·액자 추가★, 촬영 출장·야간비★, 메이크업 얼리스타트비★, 메이크업 담당자 지정★, 신부 미용(펌·염색·네일)★, 가봉스냅★, 2부 드레스★, 드레스 지정비★
- 예복·혼주: 신랑 예복, 혼주 의상, 혼주 헤어메이크업(양가)★
- 예물·예단: 예물(웨딩밴드 포함), 예단, 이바지
- 청첩·답례: 종이 청첩장, 모바일 청첩장, 청첩장 모임★, 식전영상★, 답례품★
- 신혼여행: 신혼여행
- 예비비: 교통·주차·잡비★, 당일 추가금·예비비★

## 3. 엑셀 만들기

```bash
python3 scripts/build_budget.py --input input.json --out 결혼자금계획.xlsx
```

`openpyxl`이 없으면 `pip install openpyxl`을 먼저 실행한다. 스크립트가 `입력 오류:`로 끝나면 메시지대로 JSON을 고쳐서 다시 실행한다. 실행 환경이 없으면 아래 해설만 표로 보여준다.

시트 구성: 대시보드 / 기본정보 / 하객식대 / 지출계획 / 결제기록 / 월별자금 / 기준표. 노란 칸이 입력 칸이고 나머지는 수식이다. 결제기록은 결혼 준비 내내 결제할 때마다 한 줄씩 채우는 장부라고 알려준다. openpyxl은 계산값을 저장하지 않으므로, 미리보기에서는 0이나 빈칸으로 보이고 Excel·Numbers·Google 스프레드시트에서 열면 계산된다고 안내한다.

## 4. 결과 해설

엑셀을 건넨 뒤 대화로 짧게 정리한다. 숫자는 `references/benchmarks.json`을 직접 보고 계산한다.

1. 기준값보다 20% 넘게 비싼 항목 상위 3개와 배율. 같은 상품끼리 비교한 게 아니면(`comparable: false`: 신랑 예복=턱시도 대여, 혼주 의상=한복 대여) "참고"라고 밝힌다.
2. 아직 0원인 ★ 항목. 사용자가 할 계획인지 물어본다.
3. 보증인원이 예상 하객보다 많으면 빈자리 식대(차이 × 1인 식대)
4. 가용자금 대비 부족액이나 여유액. 예상 축의금을 반영한 순부담
5. 돈이 몰리는 달 (월별자금 시트 기준)
6. 결제 내역이 있으면 신랑·신부별 결제 합계, 현금영수증을 확인해야 하는 건(계좌이체·현금인데 발급 여부 미기재·미발급)
7. 기준값은 **참가격 2026년 8월 중간값 / 듀오 2026 평균 스냅샷**이고, 업체·날짜·옵션에 따라 실제 가격은 크게 다르다고 고지한다.

하지 말 것:
- 기준값이 없는 항목(외부 본식스냅, 청첩장 모임 등)의 평균을 지어내지 않는다.
- 사용자에게 받은 이름과 금액을 다른 사람의 예시로 쓰지 않는다.
- 법률·세무·대출 조언을 하지 않는다.

- 한국소비자원 참가격 결혼서비스 통계 (2026년 8월, 중간값, 지역별): https://www.price.go.kr/tprice/portal/wedding/areaStatistic.do
- 듀오 「2026 결혼비용 실태 보고서」 (2025년 11월 조사, 최근 2년 내 결혼 1,000명, 평균, 지역 구분 없음): 예물 588만, 예단 763만, 이바지 155만, 신혼여행 1,030만, 혼수 1,445만원
- NH농협은행 2025년 평균 축의금 11.7만원
- 팁에 있는 "업계 시세" 범위(예복, 커플링, 혼주 한복, 본식스냅·영상 등)는 2026년 웨딩 플래너 안내 자료 기준이다. 판정 계산에는 쓰지 않고 설명할 때만 인용한다.
- 갱신: `references/benchmarks.json`만 고치면 된다 (`as_of`도 함께).
